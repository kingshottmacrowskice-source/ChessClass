# 弈见 · AI 国际象棋分析助手

基于需求 V1.1 实现的本地独立 Web 应用。React / TypeScript + chess.js + 浏览器真实 Stockfish 19 完整 NNUE 多线程 WASM（npm 19.0.1）。无模型时仍可走棋、分析、查看评分及回放变化；配置模型后才生成 AI 文字。没有内置演示解释或服务商密钥。

## 安装与启动

要求 Node.js 22.13+，推荐 Node.js 24、当前稳定版 Edge 或 Chrome。当前机器已安装依赖。

Windows 用户可直接双击项目目录中的 `start.bat`：脚本会检查 Node.js，在缺少依赖时自动安装，启动后自动打开浏览器。保持启动窗口开启，按 `Ctrl+C` 停止服务。固定使用 5173 端口；若端口已被占用，会显示错误，避免切换端口后无法读取原有的本地棋谱和设置。

```powershell
cd C:\Users\Administrator\Desktop\LearnChess
npm ci
npm run dev
```

打开终端显示的地址，默认 http://127.0.0.1:5173 。不要双击 HTML，也不要以 file:// 打开。首次安装需要网络；启动后棋盘与引擎资源均在本地，不依赖 CDN。首次引擎加载约 94 MiB（99 MB），需要完整刷新页面以应用多线程响应头。

当前默认采用用户截图预设：**Stockfish 19 完整版、8 秒、1 候选、15 线程、16 MB Hash**。旧版本引擎设置自动迁移，棋谱和模型配置保留。候选数为 1 时只有首选箭头；改为 3 则显示其他细箭头。Hash 仅指搜索缓存，不含网络、WASM 和线程内存。

截图中的“深度 65 CLOUD”是 Lichess 的云端缓存，不是本地 8 秒的固定深度。此处没有接入 Lichess 云评估，也不保证不同构建、线程调度的分数逐字相同。

```powershell
npm test
npm run test:browser
npm run test:proxy
npm run test:cache
npm run test:models
npm run test:openings
npm run build
npm run preview
```

`dist/` 是构建结果；预览默认 http://127.0.0.1:4173 。浏览器测试默认使用已安装的 Microsoft Edge；其他平台可在 playwright.config.ts 移除 channel 并安装 Playwright Chromium。正式发布需一起提供许可证与对应源码，见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。本次未发布到公网。

## 使用流程

1. **实际走法**：拖动棋子，或点击起点与终点。升变会要求选择后、车、象或马。右侧显示受限根搜索补算的实际着法、最佳替代、评级和对手应对。开启自动解释时，模型在证据完成且防抖后请求一次。
2. **下一步**：选择“下一步推荐”，查看真实引擎候选；点击“分析下一步”才请求模型。粗金色箭头标记当前行棋方首选，其他候选用不同颜色的细箭头显示，棋盘下方有图例，翻转棋盘后同步调整。评分统一为白方视角：正值利白、负值利黑；黑方候选按黑方利益排序，通常评分越低越好。即使候选全部为正分，仍会选择白方优势较小的走法。走法分析页评估上一手，而棋盘箭头显示当前行棋方下一步，两者有明确提示。
3. **历史复盘**：展开“导入与导出”，选择 FEN 或 PGN；导入后点击棋谱棋步。箭头按钮提供起点、前后、终点，后退即悔棋，前进即恢复。
4. **试走与回放**：历史位置走新棋建立临时分支，点击“返回原棋谱”恢复原主线。点击任何候选变化或模型“查看依据”逐步回放，支持“从这里试走”或返回分析位置。仅提供一个活动分支，无多层变例编辑。
5. **导出**：导出当前主线或分支，从起始局面直到选中棋步；文件名标明 main / branch。PGN 主线及 SetUp/FEN 标签受到支持；注释、括号变例不保留，导入区有说明。仅 FEN 导入无法恢复此前重复局面。

棋局与非敏感设置保存在 localStorage。引擎内存缓存最多 80 份，另外由项目服务使用 SQLite 保存本地局面库：缓存内容上限 2 GB，按最近访问淘汰，不设固定过期时间。数据库位于项目目录 `data/positions.sqlite`，刷新、换浏览器和重启后仍可查找。AI 棋理讲解内存缓存最多 60 份，同时持久保存到同一数据库，与引擎结果共用 2 GB 缓存内容限额。自定义直连的 API Key 仅当前页面内存有效，刷新即丢失；预设密钥由服务端文件管理。密钥均不会进入局面库或其索引。

### 本地局面库

AI 棋理讲解先查询内存和服务端数据库，命中后直接展示，不再调用模型。缓存按完整证据快照（局面、任务、候选变化、评分、深度、事实）、服务地址、模型、语言、提示词版本及引擎版本区分。服务端只保存缓存键摘要和已通过校验的讲解，不保存 API Key。读取讲解后重新校验局面和依据引用；无效记录重新生成。界面标明“来自局面库 / 来自内存缓存 / 来自模型”，设置显示讲解条数。

服务不可用时仍能调用模型生成讲解，并暂存在内存。清空分析缓存会同时删除所有浏览器共享的引擎结果与 AI 讲解；重新生成仍需可用的模型配置。持久缓存不会提升文字的真实性，棋理语义仍需复核。

每次分析先查内存，再查本地数据库，未命中才启动引擎；界面标明“本地局面库 / 内存缓存 / 本地引擎计算”和原计算时间。默认直接复用，不在后台偷偷重算。点击“强制重算”可绕过两级缓存，生成并替换记录；设置中的“清空分析缓存”同时清理局面库、引擎内存和解释缓存。

索引包括棋子位置、行棋方、易位权、有效吃过路兵格、五十回合计数，以及最近一次走兵/吃子以后的可逆局面序列。忽略不影响规则的回合编号；走兵/吃子以前的走法不要求一致，可以复用转置后的局面。当前实现保守地要求剩余历史序列相同，不把所有看起来相同的棋盘合并。引擎版本、搜索时间/深度模式、线程、Hash、候选数、受限根着法也必须一致；不把浅搜索或不同预算的结果冒充当前配置的结果。

首次遇到的新局面仍需计算，使用越多，可复用的记录越多。数据保存在运行项目服务的电脑上，同一项目的开发服务和预览服务共用 `data/positions.sqlite`，不同浏览器共享。清理浏览器数据不会删除局面库；棋谱和设置仍属于各自浏览器。服务不可用、磁盘写入失败或请求超时时自动退回内存缓存与正常搜索，稍后请求会重试。读取后重新验证主要变化合法性；损坏记录重新计算。

`start.bat`、`npm run dev` 和 `npm run preview` 均自动提供缓存接口，无需额外启动服务。纯静态托管 `dist/` 不提供缓存接口，只能使用内存缓存。默认仍只监听本机。

备份或迁移时先停止项目服务，再复制整个 `data/` 文件夹（包括可能存在的 SQLite 日志文件）。缓存内容上限为 2 GiB，数据库索引及日志会额外占用磁盘；删除缓存后数据库文件可保留空闲页供后续复用。清空分析缓存会删除所有浏览器共享的服务端记录。旧版浏览器 IndexedDB 缓存保留但不自动迁移，新分析会写入服务端数据库。

## 开局资料与 AI 翻译

默认对标准初始局面开始的前 12 回合（24 个半回合），按实际 SAN 走法顺序查询 [Wikibooks Chess Opening Theory](https://en.wikibooks.org/wiki/Chess_Opening_Theory)。不使用相似局面或父级条目冒充当前线路；仅导入 FEN 而没有完整开局历史时不匹配。

匹配到正文后，优先让已配置的模型逐段翻译成设置中的解释语言（默认中文），将译文作为棋理讲解展示。提示词要求忠实翻译，不新增评价或推荐；程序检查段落数量和棋步记号是否保持一致。页面明确标注 AI 翻译，并提供原文、具体版本、作者编辑历史和 CC BY-SA 许可。翻译准确性不能仅靠结构校验保证，可展开英文原文对照。

自动解释开启时自动翻译；关闭时点击“翻译开局文章”。没有模型配置时可先看英文原文。“改用 AI 分析”切回根据 Stockfish 证据生成的讲解。未匹配、没有可提取正文或资料服务不可用时，按原有设置使用普通 AI 分析；引擎计算和评分始终保留。设置中可关闭开局资料优先。

- 原始资料按需缓存到 `data/openings.sqlite`，最多 1,000 条、16 MiB 内容，正常有效期 30 天；不存在的条目缓存 1 天。联网失败时可使用已有的旧资料，并标注旧缓存。首次未缓存的条目需要联网。
- AI 译文存入 `data/positions.sqlite`，与普通 AI 讲解和引擎结果共享 2 GiB 内容限额。按文章内容/版本、模型、语言和翻译提示词版本区分；刷新后复用不再请求模型。清空分析缓存会删除译文，独立的 Wikibooks 原文缓存保留。
- 原文提取会省略棋盘、表格、导航和参考文献，因此以“原文节选”标注。只有分类或空表格的短条目不会伪装成完整讲解。例如用户提供的 `5. Re1` 页面在此次核查时没有可提取的正文。

## 模型配置

MiMo 和 DeepSeek 的密钥统一在项目目录 [server/models.local.json](server/models.local.json) 填写：

```json
{
  "mimo": { "apiKey": "你的 MiMo Token Plan 密钥" },
  "deepseek": { "apiKey": "你的 DeepSeek API 密钥" }
}
```

未使用的服务保留空字符串。首次获取源码可复制 `server/models.example.json` 为 `server/models.local.json`。保存后立即生效，无需重启；详情见 [服务端配置说明](server/README.md)。密钥文件已排除在 Git 和网页文件访问之外，服务端不会把密钥返回浏览器或写入局面库。

打开“分析设置 → 模型预设”选择以下任一项，再点击“测试连接”：

- **小米 MiMo 2.6 Pro**：`mimo-v2.6-pro`，使用 `https://token-plan-cn.xiaomimimo.com/v1` 和 Token Plan 专属 Key，参考[小米官方说明](https://mimo.mi.com/docs/zh-CN/tokenplan/integration/tools-overview)。
- **DeepSeek Flash**：`deepseek-flash`。
- **DeepSeek V4 Pro**：`deepseek-v4-pro`。DeepSeek 两个预设共用 `deepseek.apiKey`，调用 `https://api.deepseek.com`，模型名称参考[DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/)。

预设由项目服务端转发请求，无需额外启动代理，不受浏览器直接跨域调用的限制；开发和生产预览均支持，纯静态托管不支持。选择预设后等待上限至少为 600 秒（10 分钟），可在设置中调整到最多 1800 秒（30 分钟）。模型服务商自身的超时仍可能提前返回错误。

选择“自定义”可继续在浏览器填写 **API Base URL、模型名称、API Key** 直连其他兼容服务。自定义 Key 只留在当前页面内存，刷新即丢失；不会读取服务端密钥文件。Base 必须为 HTTP(S) 地址，不含凭据、查询参数和片段，自动添加 `/chat/completions`，已有后缀不会重复。

- OpenAI-compatible：填写服务商给出的兼容 Base（例如以 `/v1` 结束）与已开通模型名；Qwen 等兼容服务走相同协议。
- Ollama：Base 为 `http://localhost:11434/v1`，模型名必须与本机 `ollama list` 一致，一般无需 Key。先自行安装并运行相应模型。
- 请求是非流式 Chat Completions。严格 JSON 输出由提示词约束并由本地再次验证；某些弱模型可能频繁生成不合格结构，可更换模型或重试。
- 连接测试只验证接口能返回文本，不表示语义质量合格。401/403、429、其他 HTTP、网络/CORS、超时、无效 JSON 分别提示；不展示原始服务错误体。

Ollama 官方文档说明通过 `OLLAMA_ORIGINS` 配置浏览器来源，并在 Windows 修改环境变量后重新启动服务。可在退出托盘中的 Ollama 后，用新终端运行：

```powershell
$env:OLLAMA_ORIGINS='http://127.0.0.1:5173,http://localhost:5173,http://127.0.0.1:4173'
ollama serve
```

服务地址、端口改变时也要更新允许来源。HTTPS 页面访问 HTTP 服务可能受到浏览器混合内容限制。说明来源：[Ollama FAQ](https://docs.ollama.com/faq)、[OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)。

### 可选 CORS 代理

纯前端无法替不允许跨域的远程服务修改响应头。可使用项目自带的独立本地代理，独立于局面库服务：

```powershell
$env:UPSTREAM_BASE='https://你的兼容服务地址/v1'
npm run proxy
```

然后将 UI 的 Base 改为 `http://127.0.0.1:8787/v1`。代理只绑定本机、只访问启动时固定的 upstream、只允许默认开发 / 预览来源，转发内存中的 Authorization，不记录请求、Key 或服务错误正文。`ALLOWED_ORIGINS` 可设逗号分隔来源；`PROXY_PORT` 可改端口。它不是用于公开部署的多用户网关或模型管理服务器。

## 分析方法与准确性边界

- 多线程 Worker：UCI / ready 握手，搜索时间 1–60 秒（默认 8），线程 1–32（默认 15），Hash 16–1024 MB（默认 16），候选 1–5（默认 1）。生产 UI 发送 `go movetime 8000`，不附加深度 14 上限；按实际达到深度显示。单元/浏览器适配器测试仍可使用低深度模式加速验证。
- 多线程需要 SharedArrayBuffer 与跨源隔离。Vite 开发和预览均设置 `Cross-Origin-Opener-Policy: same-origin` 及 `Cross-Origin-Embedder-Policy: require-corp`；其他静态托管必须自行设置同样响应头。条件不足时明确提示，绝不静默切换回 Lite。多线程可能占用较多 CPU，可在设置中降低线程。
- 实际走法：搜索 P 最佳着法、在 P `searchmoves m` 补算实际着法、分析 Q 的对手应对。每次均使用同一时间/线程/Hash 预算，首次完成比较最多需要三次搜索（默认约 24 秒加加载时间）。MultiPV 与受限根搜索仍可能达到不同深度、产生搜索噪声，评级仅参考，不强制把未列前三的棋判为失误。
- 评分同时保留 cp/mate、原行棋方视角和白方视角。mate 距离采用 UCI 引擎回合定义，mate 0 代表行棋方已被将杀；不参与厘兵减法。
- 评级将厘兵转换为 `1/(1+exp(-0.00368208*cp))` 的估计得分代理，从走棋方视角比较。映射参考 [Lichess Accuracy](https://lichess.org/page/accuracy)，**不是使用其完整 accuracy 公式，也不是真实胜率**。本项目自定损失阈值：<2 个百分点最佳或接近最佳，<5 合理，<10 不准确，<20 失误，否则严重失误。将杀映射为胜/负端点。优势很大时可能淡化明显子力损失；不表示教学难度或人为水平。
- facts 包含吃子、将军、将杀、升变、直接攻击、落点被攻击/保护、中心 d4/e4/d5/e5 控制变化及保护关系变化。攻击按规则库几何关系计算，包含被钉子；没有完整交换评估与复杂王安全知识库。
- 模型只能引用代码生成的 evidence ID 与变化。校验任务、起始 FEN、所有必填字段、引用存在、变化逐步合法、SAN 一致、显式 UCI / 非兵 SAN 是否来自所引证据；新增结构字段拒绝。裸格名如 e4 与兵 SAN 有歧义，自由文本棋理、强制性与净赢子结论不能完全机械验证，UI 不声称全篇已证实。
- 当前语言模型置信度仅 low / medium，并说明局限；不把搜索深度换算成概率。暂无候选排名稳定性追踪或自动语义裁判。
- 取消直接终止旧 Worker，串行队列在新 Worker 重新握手，比解析 stop 后尾消息更保守。网络用 AbortController；结果绑定完整历史位置，旧结果不覆盖新局面。同一活动请求去重，两个缓存均不含 Key。

## 直播对练模式

首页右下角点击「直播对练」，或打开 `/#live`。观众执白，大肥鱼执黑，使用独立 Stockfish 实例，深度默认 2，可调整为 1–6；不会改动原分析棋局。

- 输入 Bilibili 数字直播间号后自动连接。由服务端通过 WebSocket 接收实时弹幕，同一房间的多个直播页面共享连接；页面每秒读取本机缓冲区，连接时跳过旧消息，自动去重和失败重连。设置页显示通道状态和实际收到的弹幕数量；认证成功不代表已经收到弹幕。匿名连接无消息时可按 `server/README.md` 配置本机登录信息。缓冲区最多保留 300 条，高流量或页面长时间暂停可能漏消息；缺少 UID 的消息不参与投票。
- 无需 AI 也能识别合法 UCI、SAN 和简单中文，如 `e2e4`、`e4`、`马到f3`。本地测试框可模拟不同观众。
- 每个 UID 每回合只接受第一张有效票。第一票开启回合，新观众有效票刷新 10 秒静默截止时间，总时长不超过 5 分钟。到期按票数选择，平票采用先得到票的走法。重复、歧义、非法走法不会延长计时。
- 勾选 AI 后，使用现有 `server/models.local.json` 中的 DeepSeek 密钥和 `deepseek-flash`：模糊走法每 1.5 秒最多 12 条合并识别；闲聊在弹幕停顿 2.5 秒后（最长等 10 秒）合并成一次 SSE 流式回复，不会每条弹幕触发一次。模型的走法必须再次通过棋规验证。
- 识别队列最多 30 条、界面消息最多 80 条。聊天上下文（`src/live/chatMemory.ts`）：666、哈哈哈、纯表情等刷屏不原文发送，只统计为气氛标签；同一观众 30 秒内的重复内容丢弃；多人刷同一句合并为「×N」。待回复最多 24 条，已回复历史超过 28 条时把最旧部分压缩成 ≤120 字摘要（AI 开启时由模型压缩，否则本地折叠），并附带大肥鱼最近说过的话，避免复读。首次发言的观众会被欢迎（AI 关闭时用本地台词批量欢迎）。AI 输出限制 token；每类请求同时最多一个。开始新棋局或退出时取消旧请求及引擎工作。
- 人设可以在控制台修改并保存在本机浏览器。偶尔将当前低深度 SF 评分作为聊天证据；低深度评分仅供娱乐参考。
- 走棋编排（`src/live/choreography.ts` + `src/live/fx.tsx`）：SF 给出着法后，大肥鱼先思考（至少约 1–2 秒）、用锁定框看目标格（吃子为红框），再随机选择吃法——走到被吃棋子旁**一脚踢飞**（旋转飞出棋盘 + 星星）、**一枪打碎**（弹道 + 像素碎片 + 闪光），或把自己的棋子**扔过去撞飞**对方。随后走到自己的棋子旁把它举过头顶，走到投掷点丢出：**弹两次正好落到目标格**、**落地后滑行到位**或**高抛砸落**（冲击环 + 大震屏），三选一。每次触地都有尘土和震屏。帧动画按每个动作的出招帧同步（踢腿完全伸直、开枪那一帧才命中）。
- 等待动画：每 4–9 秒随机左右张望、托腮思考、招手哼歌、去巡视当前领先的投票目标格，或在棋盘上散步；60 秒没有弹幕会打瞌睡（闭眼 + Zzz），有人发言时惊醒。
- 互动反应：弹幕从棋盘上飘过（投票弹幕高亮）；每张有效票在目标格冒出「+1」；首票、领先易主会接话；最后 3 秒棋盘中央大字倒计时。被将军、被吃子时大肥鱼会慌张挥手并冒出表情；将军时红框锁定国王并弹出 CHECK!；观众吃子时被吃的黑子会被撞飞。
- 人设可直接编辑，也可一键切换「元气女仆 / 毒舌棋圣 / 温柔老师」预设。
- 棋盘下方是像素风规则卡（6 种棋子 + 5×5 走法示意，绿点可走、红菱只能吃）和记谱法说明，并把刚走的一步翻译成中文，例如 `Nxe5+` 读作「马 吃 e5，将军」。

### 大招视频

将 MP4 / WebM / OGV 文件放入以下目录，刷新直播页面后自动扫描，同类视频随机选取：

- `public/live-videos/promotion/`：升变。
- `public/live-videos/checkmate/`：将死。

没有视频（或视频加载失败）时播放内置的像素风全屏 cut-in：速度线、立绘冲入、逐字砸出「升变！/将死！」、闪白，约 3.4 秒；大肥鱼被将死时换成冷色调并让立绘发抖。控制台的「预览升变大招 / 预览将死大招」可随时试播。视频使用全窗口遮罩，默认静音自动播放，播放结束/加载错误时关闭，也可以手动跳过。开发和预览服务都支持扫描接口，普通静态文件服务器不提供模型和弹幕接口。

### 直播像素动画与模型设置（更新）

角色通过 32×40 逻辑像素画布绘制，显示尺寸为棋盘宽度的 9%，使用 4 列 × 8 行精灵动画。待机、步行、思考、招手、搬棋步行、踢击、射击、放棋各 4 帧；落子滑行动作复用放棋帧。移动以脚底为锚点，固定每秒 1.5 格，按实际距离决定耗时；等待到达后才执行吃子或搬棋。六类棋子使用独立 16×18 像素图案。

直播右栏「直播控制台 → 模型参数」可分别选择走法识别和聊天模型，设置聊天温度、识别/聊天最大输出 token、超时。参数自动保存到当前浏览器，下次请求生效；识别温度固定 0。支持项目现有 DeepSeek Flash / V4 Pro 预设，默认都为 Flash。API 密钥仍填写 `server/models.local.json` 的 `deepseek.apiKey`，保存文件后下次请求读取，不发送给浏览器。棋力在同一控制台的 Stockfish 深度滑块调整，与聊天模型分开。

### 等分棋盘与自然走棋点评

棋盘显式固定为 8×8 等分网格，棋子不会再撑高所在行。走棋点评默认每回合 35% 概率，可在直播控制台「走棋点评频率」调整（0% 关闭、100% 每回合）。点评覆盖观众落子后的应对和大肥鱼自己落子的打算，后台传入实际 SF 搜索深度、评分、所选走法与最多 6 步合法变化。气泡使用角色自己的口吻，不播报引擎指标或免责声明。启用 AI 时流式生成；未启用/服务失败时用实际棋局生成简短反应。最新点评保留在「大肥鱼刚刚说」。新回合、重开局及退出取消旧点评，避免串局。

### 独立动作素材与动作放映室

打开 `/#actions`，或点击直播页右上角「动作预览 ↗」（新标签页，不中断原棋局）。9 个动作分别重新生成在 `public/live/actions-v2/`：待机、行走、思考、招手、举棋行走、踢击、射击、放下、推滑。每张 PNG 为独立 3×2、6 帧透明动画表，共 54 帧；保留旧素材用于回退。播放器统一使用 32×40 逻辑像素画布，并按各帧不透明像素底边对齐脚底，避免腿脚上下漂移。攻击与落子动作播放一次，待机和行走循环播放。

动作放映室支持播放/暂停/重播、上一帧/下一帧、点击六帧缩略图、转向、播放速度、放大倍率、棋盘脚底基准线和固定速度行走演示。与直播页共用 Sprite 播放器，可打开当前动作原图。

头顶气泡不再常驻：展示时间为 `1200 + 非空白字符数 × 210` 毫秒，限制在 2.2–14 秒。流式回复期间保持显示，结束或失败后按当前文字计时；新台词替换旧台词，旧请求不能重置新气泡计时。预览页底部可输入文字测试停留时间。
